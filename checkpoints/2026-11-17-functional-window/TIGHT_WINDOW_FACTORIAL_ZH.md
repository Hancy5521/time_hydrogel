# 紧时窗见证片厚度和测量通道的同批比较

这次补齐此前缺少的标准厚度加早期电学对照。研究对象为早期见证片，最终补片的 27 个工艺候选均固定。四种测法在新母批上让同一套 ExtraTrees 分别选一个候选，以完整安装、工作和弱湿条款都通过作为选对。紧时间窗仍是安装至 1.8、工作 3.2–4.8，均为模拟时间。

四组共用五个早期标量，见证片在 0.4 时测一次中层含水，在 0.8 时再测一个标量。相同厚度的两个通道以同一个第一读数作为输入。厚度改变时，第一读数的物理值可以随见证片的水化过程改变。保持薄片和标准片的离子面库存及外侧浴液条件，所有组均只用两次见证片读数。仿真水化噪声标准差为 .016，对数电导为 .08。实际仪器时间、噪声与成本仍待测定。两类生成机制各自进行前向计算；电学读数没有直接用作主片的未来电导。 [冻结协议](runs/patch_tight_factorial_20261117T043535980478Z/REGISTERED.json)

四个模型使用相同的 224 个原训练母批、四折整母批交叉拟合、有符号余量和配对联合残差。新开发批只用于检查风险规则能否锁定。独立的 480 个确认母批专门检验事前登记的无门槛选材终点，使用固定的违规概率与违规幅度排序。每母批的两个请求一起重采样，并以母批为单位计算配对区间。该试验的用途和完整主证据中的八项工作负荷不同。

## 新的独立模拟证据

960 项请求中 590 项在固定候选目录里可行。四种测法表现如下。

| 见证片 | 第二读数为含水 | 第二读数为电导 |
|---|---:|---:|
| 标准厚度 | 270/960 | 277/960 |
| 0.65 倍厚度 | 271/960 | 315/960 |

| 登记对照 | 配对差（百分点） | 边际 95% 区间 | 五项对照校正区间 |
|---|---:|---:|---:|
| 电学通道下薄片减去标准片 | +3.96 | [1.56, 6.35] | [0.73, 7.19] |
| 含水通道下薄片减去标准片 | +0.10 | [−2.19, 2.40] | [−2.92, 3.02] |
| 标准片中电导减去含水 | +0.73 | [−1.67, 3.13] | [−2.40, 3.85] |
| 薄片中电导减去含水 | +4.58 | [1.98, 7.29] | [1.04, 8.13] |
| 厚度与通道交互差 | +3.85 | [0.52, 7.19] | [−0.52, 8.23] |

减薄改善了电学通道下的选材，薄片上的电学读数也优于薄片上的第二次含水读数。校正后，观测仍不足以给出明确的交互效应。相对标准厚度的电学方案，薄片电学方案的正向收益在原机制与交换机制中分别为 3.13 和 4.79 个百分点，单列为描述结果。仍有 275 项可行请求没有选对，其中 177 项由安装期过早导通、91 项由工作期未及时导通、7 项由弱湿误通限制。 [冻结确认评分](runs/patch_tight_factorial_20261117T043535980478Z/CONFIRMATION_SUMMARY.json)

独立的 160 个开发母批中，四种方案均未达到登记的最低活跃度与开发风险条件。风险校准未启动，确认数据只用于本次事前登记的无门槛选材。原 640 母批的 **+3.95 个百分点**是另一项关于最终补片制造厚度的同风险达标交付结果。 [开发及锁定结果](runs/patch_tight_factorial_20261117T043535980478Z/DEVELOPMENT_SUMMARY.json)

## 复算

`tight_window_factorial.py` 是本轮新增程序，原程序和冻结批次继续保留。`audit_tight_window_factorial.py` 独立核对两个生成阶段的来源散列、冻结时序、全候选动作排名、所有方案达标数、区间和门槛选择。对两类生成机制各检查一个见证片输入，同前一版重合的三组输入一致，新实验四组共用相同的前五个早期标量并且保持同厚度的第一含水读数一致。 [复算记录](runs/patch_tight_factorial_20261117T043535980478Z/FACTORIAL_AUDIT.json)

```powershell
$p='runs/patch_tight_factorial_20261117T043535980478Z'
python -B tight_window_factorial.py forecast $p development
python -B tight_window_factorial.py score $p development
python -B tight_window_factorial.py forecast $p confirmation
python -B tight_window_factorial.py score $p confirmation
python -B audit_tight_window_factorial.py $p
```

从头复算时，将 `REGISTERED.json` 复制到空的运行目录并替换 `$p`。保留原项目相对路径上的上游训练资料。每条命令都拒绝覆盖已存在的阶段文件。若开发阶段存在锁定的规则，须先执行同样的 `forecast` 和 `score` 校准步骤。
